# SPEC-29: AXIS mode-usage report, latency and refusal summary, static HTML report, and the thumbs signal (ADR-0035 plan step 8, part 2)

Status: **Approved by the owner 2026-11-20** ("Go, all eight as recommended"): spec and the eight open points in section 7 as recommended. Next step is tests first; no code until the tests are written and shown failing.
Implements: ADR-0037 sections 2.3 (span summary), 2.4 (mode-usage report), 2.6 (thumbs), 2.7 (static HTML report; the live page SPEC-29b stays out) and the confirmed open points 4.1 and 4.4 (UTC Monday week). Builds on SPEC-28 (merged, #63): it reads the trace file SPEC-28 writes.
Does **not** implement: the obedience eval and `AXIS_TEMPERATURE` (SPEC-30), any live dashboard page or HTTP endpoint for the report (SPEC-29b, needs an owner/admin gate first), vendor adapters (ADR-0038).
Governed by: AGENTS.md (no learner text outside the process, zero-cost offline), ADR-0022 (interaction log: append-only, never the evidence ledger), ADR-0035 section 5.4 (10 s timeout, 2 concurrent searches), SPEC-24 and SPEC-27 (retrieval statuses).

## 0. What the code shows (checked 2026-11-20)

1. **The interaction log is append-only, keyed by `(learner_id, interaction_id)` with `INSERT OR IGNORE`.** A thumbs row that reused the AXIS turn's `interaction_id` would be silently ignored. So the vote carries the turn id **in its payload** and gets its own row id.
2. **`axis` rows already hold `payload.mode`** (`Socratic`, `Hybrid`, `Coach`), `unit_id`, `recorded_at_ms` and a `test_mode` column. Both `consult_axis` and the stream route write them, with the `interaction_id` SPEC-28 now mints first. The log has **no read across learners**: `get_interactions(learner_id, limit)` is per learner and newest first. A report needs one new read-only repository method.
3. **The browser never sees the turn's id.** The panel uses the stream route only; the `done` event carries `assistance_level`, `cited_concepts`, `source_state`, `retrieval_downgraded`. The UI cannot name a turn to rate until the server returns its `interaction_id` in `done`.
4. **`ClientEvent` / `ClientPayload` are `extra="forbid"`** and `ClientEventType` is a closed `Literal`; `POST /api/v1/learners/me/interactions` copies `unit_id`, `activity`, `item_id` from the client. A vote must not let the client claim another learner's turn or invent a unit.
5. **Busy and timeout cannot be told apart in the spans today.** `RetrievalStatus` is `ok | not_found | no_index | unavailable`. A busy search returns `unavailable` with the free-text message `busy: too many searches at once`; a timeout, a stalled pool, a start failure and a model fault all return the keyword fallback with `downgraded=True` and a free-text reason in a log line only. `RetrievalTrace` and the `retrieve` span carry no reason. ADR-0035 5.4 asks step 8 to re-measure exactly these two settings, so the report needs a structured reason (R17).
6. **Spans have `duration_ms` and attributes** (SPEC-28): `retrieve` (retrieval status, mode, `downgraded`, `latency_ms`, counts), `model_call` (call, `mock`, `reason`, tokens), `prompt_build`, `citation_check`, `check_requirements`, `feedback_points`; roots carry `kind`, `mode`, `test_mode`, `stream`. The trace file is `data/traces/axis-trace.jsonl` plus one rotated `.1`; a torn last line is possible.
7. The repository has **one** implementation (`SQLiteLearnerRepository`) of `ILearnerRepository`. `frontend/src/api/schema.d.ts` is generated by `npm run types`.
8. `lms` is a hand-rolled command dispatcher (`src/lms/__init__.py`, handlers in `src/lms/cli.py`). There is no sub-command framework.

## 1. Why

ADR-0035 5.5 (revisit step 6b after real use) needs evidence of which modes learners use, in which units, over time. ADR-0035 5.4 needs real numbers for the ten second timeout and the two concurrent searches. ADR-0037 asks for a thumbs signal so a person can see whether answers help. None of this exists yet. This spec adds the readers and the one learner-facing control, and nothing that changes an answer.

## 2. Requirements

### A. Mode-usage report (from the interaction log)
- R1. `lms report axis-modes` reads `interaction_log` rows with `event_type=axis` and prints, in this order: a header line stating **"Weeks run Monday to Sunday, UTC."**; a table **per mode**; a table **per mode and unit**; a table **per mode and week**. Each table has the columns `turns` and, **only when more than one distinct learner appears in the data**, `learners`. Counts only: no question, answer, id or text of any kind.
- R2. A row with a missing, empty or unrecognised `payload.mode` is counted under the mode `unknown`. A row is never dropped for a bad payload (a payload that is not a JSON object counts as `unknown` too).
- R3. Rows with `test_mode=1` are **excluded by default**; `--include-test-mode` includes them. The header says which it is ("test_mode rows: excluded" or "included").
- R4. Week = the UTC Monday (00:00:00.000) on or before `recorded_at_ms`, shown as an ISO date (`2026-11-16`). Boundaries are exact: Sunday 23:59:59.999 UTC belongs to the earlier week, Monday 00:00:00.000 to the next. Rows with `unit_id` null are grouped under `(none)`.
- R5. **Thumbs counts per mode** appear in the first table: `up` and `down`, taken from `axis_feedback` rows (R20 to R28): per learner and turn the **latest** vote counts (ordered by `recorded_at_ms`, then `interaction_id`); a latest vote of `clear` counts as no vote; a vote whose turn is not an `axis` row in the data, or whose turn is excluded by R3, is not counted. The mode of a vote is the mode of its turn.
- R6. Output is a plain fixed-width table by default and `--json` prints one JSON object (`sort_keys`, UTF-8) with the same numbers. Deterministic: ties sorted by key, **no timestamps and no clock value** in the numbers or the header. Optional `--db PATH` (default `LMS_DB_PATH`, as the server).
- R7. **Read-only.** The report opens the database for reading, never writes, never creates a missing file (a missing database prints "No interaction log found at <path>" and exits 0 with no table). An empty log prints the header and "No AXIS turns recorded." and exits 0.
- R8. The aggregation is a **pure function in `core/`** (`lms.core.axis_report`): events in, plain data out. Neither it nor the CLI reads text from payloads except `mode` and the two thumbs fields.

### B. Latency and refusal summary (from the SPEC-28 trace file)
- R9. `lms report axis-latency` reads `axis-trace.jsonl.1` then `axis-trace.jsonl` from `LMS_TRACE_DIR` (default `data/traces`; `--trace-dir` overrides) and prints, per **stage** (span name: `retrieve`, `prompt_build`, `model_call`, `citation_check`, `check_requirements`, `feedback_points`) and per **trace kind** (the root span name), `n`, `p50`, `p95` and `max` of `duration_ms`. Percentiles use the **nearest-rank** method. A row with `n` below 20 is marked `(few)`; the report never hides a small sample.
- R10. **Tolerant reading.** A missing folder or file, an empty file, a missing rotated file, a torn or non-JSON line, a line that is not an object, a record without `name` or with a non-integer `duration_ms`, and unknown extra fields are all handled without raising: bad lines are skipped and counted (`skipped_lines` is printed when above 0). Nothing here may read or print any attribute that is not on SPEC-28's allow-list.
- R11. Traces whose root span has `test_mode=true` are excluded with all their children by default (`--include-test-mode` includes them). A span with no root in the file (a rotated-away parent, or a call from `lms ask`) is counted by stage and is not treated as test mode.
- R12. **Counts** over `axis_question` traces that have a `retrieve` span: `retrieval_status` (`ok`, `not_found`, `no_index`, `unavailable`), `downgraded`, and `retrieval_reason` (R17: `busy`, `timeout`, `stalled`, `start_failed`, `model_fault`), plus a **refusal rate** = `not_found + no_index + unavailable` over those traces. Over `model_call` spans: counts of `status=error` by `reason` and the count of `mock=true` and of `fallback=mock`.
- R13. The header prints the **settings in force when the report runs** (`LMS_RETRIEVAL_TIMEOUT_S`, `LMS_RERANK_CONCURRENCY`, through the same readers `startup.py` uses), so a number can be read against the limit. It also prints the largest `retrieve` `latency_ms`. It never claims a verdict: no "timeout too high" text.
- R14. `--json` prints the same numbers as one object. Same determinism and read-only rules as R6 and R7. An empty or absent trace set prints "No traces recorded yet. Set LMS_TRACER=local (the default under `lms serve`) and use AXIS." and exits 0.
- R15. **Re-measure procedure (not code).** After the owner runs a real local-model session in hybrid mode (`LMS_RETRIEVAL_MODE=hybrid_rerank`, `LMS_TRACER=local`), `lms report axis-latency` supplies: retrieve p50/p95/max against the 10 s limit, and the counts of `timeout`, `stalled` and `busy`. The owner records the result in ADR-0035 5.4 in a separate docs change. One learner cannot exercise the concurrency limit of 2; a load run is **out of scope** here (open point 6).
- R16. The aggregation (R9 to R14) is a **pure function in `core/`** over already-parsed records; file reading, torn-line handling and the CLI live in an adapter.
- R17. **A structured retrieval reason (small additive change to SPEC-27 and SPEC-28).**
  - `RetrievalResult` and `RetrievalTrace` gain `reason: str = ""`. Allowed values: `""` (none), `busy`, `timeout`, `stalled`, `start_failed`, `model_fault`.
  - `RagcoreRetriever` sets it where it already decides: `busy` on the "too many searches at once" `unavailable` result; `stalled`, `timeout`, `start_failed`, `model_fault` on the four `_downgrade` paths. Behaviour, messages, statuses and the learner-facing label are unchanged.
  - The SPEC-28 allow-list gains `retrieval_reason`, valid only from that fixed set; the `retrieve` span sets it when non-empty.
  - Without this change `busy` and `timeout` cannot be told apart (finding 5).

### C. Static HTML report
- R18. `lms report axis-html [--out FILE]` writes **one self-contained HTML file** (default `data/reports/axis-report.html`, folder created if missing) holding the R1 to R5 tables and the R9 to R14 tables, built from the same aggregates (never re-reading raw text). **No JavaScript, no external asset of any kind** (no link, script, image, font or import), inline CSS only, light and dark by `prefers-color-scheme`, and a `<meta http-equiv="Content-Security-Policy" content="default-src 'none'; style-src 'unsafe-inline'">`. It works opened from disk with no network.
- R19. Every value placed in the HTML is **escaped** (`html.escape`, quotes included), including mode names, unit ids and trace kinds, even though they should be plain tokens. The file holds counts, mode names, unit ids, weeks and timings only: **no learner id, no interaction id, no trace id, no span id, no passage id, no text**. Tables use `<caption>`, `<th scope>` and real `<table>` markup; nothing is conveyed by colour alone. The write is atomic (write a temporary file in the same folder, then `os.replace`); a failed write leaves any older report untouched and reports the error class only. A header says the report is a local owner view, not a learner page.

### D. Thumbs up/down
- R20. A new client event type **`axis_feedback`** is added to `EventType` and `ClientEventType`. It carries only two payload fields, both new on `ClientPayload` (which stays `extra="forbid"`): `turn_id` (the AXIS turn's `interaction_id`, the same ID pattern) and `vote` (`up`, `down` or `clear`). No free text.
- R21. `ClientEvent` validation: for `axis_feedback` both fields are required; for every other event type both are **forbidden**; `interaction_id`, `unit_id`, `activity` and `item_id` sent by the client on an `axis_feedback` event are ignored, not trusted.
- R22. The server **checks the turn**: it must be an `axis` row of **this** learner (new read-only repository method `get_interaction(learner_id, interaction_id)`). An unknown id, another learner's id, or an id that is not an `axis` row returns **404** with the usual problem body and writes nothing. A malformed id or vote is refused by validation (422) as for any bad client event.
- R23. The row that is written gets a **fresh server-minted `interaction_id`** (never the turn's), `unit_id` and `activity` copied from the turn's row, and `payload={"turn_id": ..., "vote": ...}`. `test_mode` follows the app's mode as for every row.
- R24. **Never the evidence ledger, and never anything else.** An `axis_feedback` event writes no evidence entry, no assistance level, no attempt, no skill estimate, no cold-check or progression state, and never changes the soft gate or a verdict. (A test counts every table before and after.)
- R25. **One vote per answer, changeable.** The log stays append-only: each change is a new row, and the latest row per `(learner, turn_id)` is the vote (R5). `clear` withdraws it.
- R26. The stream route adds `interaction_id` (its server-minted turn id) to the **`done` event data**. The consult response is unchanged (the panel does not use it). A blocked or errored turn has no `done` and so no thumbs control.
- R27. **Frontend control** (`AxisPanel`): under each finished AXIS answer, a `role="group"` labelled "Rate this answer" with two native `<button>`s, "Helpful" and "Not helpful", each with `aria-pressed`. The chosen button shows a visible tick and bold text (**state is never by colour alone**); pressing the chosen button again sends `clear`. Fully keyboard operable (Tab, Enter, Space). Not shown while the reply is streaming, on an error, or for a blocked turn. A `role="status"` line (polite) says "Thanks, noted." after a saved vote and "Could not save your rating." after a failure, in which case the buttons return to their previous state. No retry loop.
- R28. The control sends one request per press to `POST /api/v1/learners/me/interactions`, never blocks the conversation (a pending vote does not disable the question box), and does not change the answer, its citations or its notes. `frontend/src/api/schema.d.ts` is regenerated (`npm run types`) and the contract test stays green.

## 6. Chaos check (step 5 of the loop; each becomes a test or a recorded finding)
- **Log data:** a million-row log (the report must stream rows, not hold them); `recorded_at_ms` of 0, negative, far future, or non-integer text; two rows with the same millisecond; `payload` of `[]`, `null`, a string, or deeply nested; `mode` of 10 KB, with a newline, or `"coach"` in the wrong case (stays `unknown`); a vote that precedes its turn; a vote for a turn in another week; two learners voting on the same turn id; 10,000 votes by one learner on one turn.
- **Trace file:** a 10 MB file with one torn final line; a file of only blank lines; a file that is a directory; the rotated file newer than the current one; `duration_ms` of `-1`, `1e9`, `true`, `"12"`; a span whose attributes are `null`; ten thousand spans in one trace; clock skew (`started_at_ms` out of order is fine: only durations are used); a trace file written by a later SPEC-28 version with new keys.
- **HTML:** a unit id or mode containing `<script>`, `"`, `'`, `&`, `</table>`, or a null byte; an output path in a missing folder, on a read-only folder, or equal to the trace or database file (refuse); a second report run while the first file is open in a browser (Windows).
- **Thumbs:** double click; click then reload; a vote while the stream is still open (the control is not shown, and the server refuses a turn that is not logged yet); a replayed POST; a forged `turn_id` of another learner or a made-up ULID; a vote on a turn from `test_mode` while the report excludes it; rapid up/down/up with out-of-order responses (the last press wins on screen, the latest row wins in the report).
- **CLI:** `lms report` with no name, `lms report axis-modes --db <missing>`, a database that is not SQLite, a locked database (read-only open must not wait forever or write a journal), non-UTF-8 console.

## 7. Open points (decided by the owner 2026-11-20: all eight as recommended)
1. **A structured retrieval reason (R17).** Without it the report can say "unavailable" but cannot tell a busy search from a timeout, which is the whole point of re-measuring ADR-0035 5.4. It is a small additive change to the SPEC-27 adapter and the SPEC-28 allow-list, with no change to what a learner sees. *Recommended: yes.* Alternative: infer timeouts from latency near 10 s and report `busy` inside `unavailable`, which is guesswork.
2. **A "clear" vote (R20, R25).** Pressing the chosen button again withdraws the rating, so a mis-click is not permanent. *Recommended: yes.* Alternative: only up or down, changeable but never removable.
3. **Where the turn id comes from (R26).** Add `interaction_id` to the stream's `done` event only. *Recommended.* Also adding it to the consult response would change the API schema for a route the panel does not use.
4. **Two new read-only repository methods (`get_interaction`, `iter_interactions`).** They add to the repository interface (one implementation exists). *Recommended.* Alternative: the report opens the SQLite file directly with its own SQL, which bypasses the port and would break if the store changes.
5. **Command names and the HTML location.** `lms report axis-modes | axis-latency | axis-html`, HTML at `data/reports/axis-report.html` (git-ignored with `data/`). *Recommended as is.*
6. **Concurrency re-measure (R15).** One learner cannot make two searches overlap, so SPEC-29 gives you the `busy` count from real use but does not prove the limit of 2. A small load script (`scripts/measure_hybrid_load.py`, local, owner-run) would do it. *Recommended: not in SPEC-29; add later if `busy` shows up or you want the number.*
7. **Small samples.** Rows under 20 are marked `(few)`, and percentiles are nearest-rank. *Recommended.* Alternative: hide rows under 20, which hides what a single-learner run produces.
8. **Thumbs wording.** "Helpful" and "Not helpful", with a tick on the chosen one. *Recommended*; the labels are yours to change.

## 8. Out of scope
The obedience eval, `AXIS_TEMPERATURE` and the answer checks (SPEC-30); the live dashboard page and any report endpoint (SPEC-29b, needs an admin gate); per-learner views (the report is counts across learners only); vendor adapters and LangSmith (ADR-0038); changing what AXIS answers, how it retrieves, or any threshold; recording the re-measure result in ADR-0035 5.4 (a separate docs change after a real run).
