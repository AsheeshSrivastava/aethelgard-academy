# Glossary

Domain terms used across the code, specs and screens. Add a term when it is settled.

| Term | Meaning | Notes |
|---|---|---|
| **stage** / **Module** | A group of units in a course, in path order, ending in a stage review and a build. | stage (code, data, roadmaps, ADRs) = Module (anything a learner reads). Never rename code identifiers; change labels only (ADR-0027). Slotted roadmaps keep their own labels ("DSA 0", ADR-0020). |
| **unit** | One lesson with 1 to 3 target skills and 2 to 3 methods. | |
| **Cold Check** | The unit's own end check, done without AXIS (ADR-0019). | |
| **stage review** / **module review** | A mix of spare Cold Check items from every unit of a stage; passing it opens the build (ADR-0019). | Learners read "module review". |
| **build** | The stage's project step: a small program and README for the case study (SPEC-15). | Learners read "Module N build". |
